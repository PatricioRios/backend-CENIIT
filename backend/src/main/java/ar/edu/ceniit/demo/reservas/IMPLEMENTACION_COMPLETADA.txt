┌─────────────────────────────────────────────────────────────────────────────┐
│ PERSISTENCE LAYER (ReservasPersistenceAdapter.java)                         │
└─────────────────────────────────────────────────────────────────────────────┘

✅ existeReserva(Integer recursoId, OffsetDateTime fechaHora)
   - Query con Specification para validar si existe reserva en fecha exacta
   - Excluye reservas canceladas
   - Retorna: boolean

✅ existeReservaInRange(Integer recursoId, OffsetDateTime inicio, OffsetDateTime fin)
   - Lógica de solapamiento de rangos:
     * (existente.fin > nuevo.inicio) AND (existente.inicio < nuevo.fin)
   - Excluye reservas canceladas
   - Usado para validar conflictos antes de crear reserva
   - Retorna: boolean

✅ createReserva(Reserva reserva, Integer solicitanteId)
   - Mapea domain → entity
   - Establece estado PENDIENTE por defecto
   - Guarda en BD con save()
   - Retorna: Reserva (domain) con ID generado

✅ updateReserva(Reserva reserva)
   - Busca reserva existente por ID
   - Lanza ReservaNotFoundException si no existe
   - Actualiza solo campos presentes (estado, aprobadorId)
   - Guarda cambios
   - Retorna: Reserva actualizada

✅ findReservasByRecursoAndRange(...) [YA IMPLEMENTADO ANTES]
   - Query paginada con filtros de recurso y rango de fechas
   - Soporta criterios adicionales (solicitante, aprobador)
   - Retorna: PagedResult<Reserva>
