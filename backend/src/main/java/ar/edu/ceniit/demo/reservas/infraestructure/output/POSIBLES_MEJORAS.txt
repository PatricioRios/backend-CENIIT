┌─────────────────────────────────────────────────────────────────────────────┐
│ PROBLEMA ACTUAL                                                              │

- HTTP 200 OK
- Response: { "content": [], "totalElements": 0, ... }

AMBIGÜEDAD: ¿El recurso existe pero no tiene reservas, o el recurso no existe?

┌─────────────────────────────────────────────────────────────────────────────┐

Validar existencia del recurso ANTES de buscar reservas:
- Si recurso NO existe → HTTP 404 Not Found

MEJORA #2: VERIFICAR DISPONIBILIDAD DEL RECURSO (ESCENARIO 3)
═══════════════════════════════════════════════════════════════════════════════

┌─────────────────────────────────────────────────────────────────────────────┐
│ PROBLEMA ACTUAL                                                              │
└─────────────────────────────────────────────────────────────────────────────┘

Si un recurso está EN_MANTENIMIENTO o INACTIVO, se devuelven sus reservas
normalmente. Esto puede causar confusión:

- Usuario ve reservas de un recurso que no está disponible
- Frontend debe validar estado por separado
- Posibles inconsistencias en UI

┌─────────────────────────────────────────────────────────────────────────────┐
│ SOLUCIÓN PROPUESTA                                                           │
└─────────────────────────────────────────────────────────────────────────────┘

OPCIÓN 1: Filtrar reservas según estado del recurso
OPCIÓN 2: Agregar metadatos del recurso en respuesta
OPCIÓN 3: Lanzar error si recurso no disponible

│ IMPLEMENTACIÓN - OPCIÓN 1: FILTRAR RESERVAS                                 │

// 1. Obtener estado del recurso
EstadoRecurso estadoRecurso = recursoService.getEstado(recursoId);

// 2. Modificar query según estado
@Override
public PagedResult<Reserva> findReservasByRecursoAndRange(...) {
    // Obtener estado del recurso
    EstadoRecurso estadoRecurso = getEstadoRecurso(recursoId);
    
    // Si está en mantenimiento, solo mostrar reservas pasadas
    OffsetDateTime fechaDesdeAjustada = fechaDesde;
    OffsetDateTime fechaHastaAjustada = fechaHasta;
    
    if (estadoRecurso == EstadoRecurso.EN_MANTENIMIENTO) {
        // Solo mostrar reservas que ya pasaron
        fechaHastaAjustada = OffsetDateTime.now();
    }
    
    // Construir query con fechas ajustadas
    Specification<ReservaEntityTable> baseSpec = (root, query, builder) -> {
        Predicate recursoIdPredicate = builder.equal(
            root.get("recursoSolicitadoId"), recursoId.intValue());
        Predicate fechaInicioPredicate = builder.greaterThanOrEqualTo(
            root.get("fechaHoraInicio"), fechaDesdeAjustada);
        Predicate fechaFinPredicate = builder.lessThanOrEqualTo(
            root.get("fechaHoraFin"), fechaHastaAjustada);
        
        return builder.and(recursoIdPredicate, fechaInicioPredicate, fechaFinPredicate);
    };
    
    // ... resto de la implementación
}

private EstadoRecurso getEstadoRecurso(Long recursoId) {
    // Opción A: Query directo a tabla recursos
    return recursoRepository.findById(recursoId.intValue())
        .map(RecursoEntity::getEstado)
        .orElse(EstadoRecurso.DISPONIBLE);

    // return recursosClient.getEstado(recursoId);
